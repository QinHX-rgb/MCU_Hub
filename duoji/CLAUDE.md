- **Target**: MSPM0G3507 (Cortex-M0+, 32MHz, no FPU) on the LP-MSPM0G3507 LaunchPad

- **SDK**: MSPM0-SDK v2.11.0.07

### Initialization order

```
SYSCFG_DL_init()                      // generated by SysConfig — all hardware
  ├─ initPower, GPIO, SYSCTL (32MHz)
  ├─ SERVO (TIMA0 PWM, PA8, 50Hz, CC=3000)
  ├─ I2C_OLED (I2C0, PA28=SDA, PA31=SCL, 400kHz)
  ├─ UART_K230 (UART1, PB6/PB7, 115200)
  ├─ UART_0 (UART0, PA10/PA11, 115200)
  └─ SYSTICK (1μs ticks, no interrupt)

main():
  ├─ servo_set_angle(BALANCE_ANGLE)   // immediate: correct PWM from 90° to balance angle
  ├─ PA18 pull-down (override SysConfig NO_PULL)
  ├─ balance_init()                   // PID, servo→balance angle, UART banner
  └─ while(1): btn_poll() + balance_poll()
```

### Dual UART Architecture

| UART | Instance | Pins | Direction | Purpose |
|---|---|---|---|---|
| UART1 | `UART_K230` | PB7=RX, PB6=TX | K230 → MSPM0 | Ball position data input (`$BALL,...` frames) |
| UART0 | `UART_0` | PA10=TX, PA11=RX | MSPM0 → PC | Debug output via XDS110 virtual COM port |

- **K230 UART (UART1)**: Polled in `balance_poll()` via `DL_UART_Main_receiveDataCheck()`. No ISR — main loop drains bytes directly into a ring buffer.
- **Debug UART (UART0)**: Blocking transmit only. `uart_debug_printf()` for status output.

### Three-Button System (in `empty.c`)

State machine: `SYS_SELECT → SYS_ARMED → SYS_RUNNING`

| Button | GPIO | SysConfig Name | Resistor | Active | Edge | Function |
|---|---|---|---|---|---|---|
| PA18 | PINCM40 | `GPIO_KEY_PIN_BUTTON` | Pull-down (manual) | Press=HIGH | Rising (0→1) | Start/Stop balance |
| PA13 | PINCM35 | `GPIO_KEY_PIN_0` | Pull-up (SysConfig) | Press=LOW | Falling (1→0) | Sequence mode (0→+50→-50) |
| PA12 | PINCM34 | `GPIO_KEY_PIN_1` | Pull-up (SysConfig) | Press=LOW | Falling (1→0) | Center mode (hold 0mm) |

**Flow:**
1. Power-on → servo at `BALANCE_ANGLE`, LED off, `SYS_SELECT` — waiting for mode choice
2. Press **PA13** → LED on, `SYS_ARMED`, Sequence mode selected
3. Press **PA12** → LED on, `SYS_ARMED`, Center mode selected
4. Press **PA18** → LED off, `SYS_RUNNING`, balance starts. Sequence runs automatically if that mode was selected.
5. Press **PA18** again → back to `SYS_SELECT`, servo locked at `BALANCE_ANGLE`
6. During running, PA13/PA12 can switch modes on the fly

All buttons have 30-iteration (~30ms) debounce cooldown.

### LED Indicator

| GPIO | SysConfig Name | Purpose |
|---|---|---|
| PA0 (PINCM1) | `GPIO_LED_PIN_2` | OFF=selecting/stopped, ON=mode selected, OFF=running |

## K230 Serial Protocol

```
$BALL,帧号,有效标志,位置mm,目标mm,置信度,帧间隔ms#\n
```

Example: `$BALL,1234,1,12.5,0.0,0.95,33#\n`

Fields: frame header, frame number, valid flag (1=tracking, 0=calibrating), position (mm), target (mm), confidence (0~1), frame interval (ms). Parser (`parse_frame()` in `balance.c`) uses `strtof()`; requires trailing `#`. Both valid and invalid frames trigger PID when enabled.

### Sign Convention

- **BALANCE_ANGLE**: The servo angle where the pipe is horizontal (neutral). Currently **55°** — hardware-dependent, tune first.
- **error = position_mm - setpoint** (setpoint = 0.0mm)
- **angle = BALANCE_ANGLE + PID_output**
- Positive position (ball right) → PID output increases → servo angle increases → pipe tilts → ball rolls left

## Balance Control API (`drivers/balance.h`)

### Core functions

| Function | Purpose |
|---|---|
| `balance_init()` | Init ring buffer, PID, servo→BALANCE_ANGLE, print startup banner via UART |
| `balance_poll()` | Drain K230 UART1 → parse `$BALL` frames → sequence timer + PID (if enabled) |
| `balance_set_setpoint(float sp)` | Change target position (default 0.0mm), resets PID integral |
| `balance_get_setpoint_mm()` | Returns current setpoint as integer mm |

### Control API (called from main)

| Function | Purpose |
|---|---|
| `balance_enable()` | Enable PID control, reset setpoint to 0 |
| `balance_disable()` | Disable PID, lock servo at BALANCE_ANGLE |
| `balance_is_enabled()` | Returns 1 if PID is active |
| `balance_start_sequence()` | Start setpoint sequence: center → +50mm → -50mm → hold |
| `balance_cancel_sequence()` | Cancel sequence, hold at 0mm |
| `balance_is_sequence_running()` | Returns 1 if sequence is in progress |

### Setpoint Sequence (auto-runs when enabled + sequence mode)

The sequence uses **ramp transitions** — setpoint moves smoothly at `SEQ_RAMP_RATE` mm/s rather than jumping, to prevent overshoot. PID integral is NOT reset during ramp.

1. **Center** (0mm) — `SEQ_HOLD_CENTER_MS` (150ms)
2. **Right** (+50mm) — `SEQ_HOLD_RIGHT_MS` (1800ms)
3. **Left** (-50mm) — `SEQ_HOLD_LEFT_MS` (3050ms)
4. **Hold** at -50mm indefinitely

Timing uses `dt_ms` from K230 frames. Phase durations and ramp rate are configurable in `balance.h`.

### PID Tuning Constants (in `balance.h`)

| Constant | Value | Purpose |
|---|---|---|
| `BALANCE_ANGLE` | 55 | Neutral servo angle — **hardware-dependent, tune this first** |
| `BALANCE_KP` | 1.52 | Proportional gain |
| `BALANCE_KI` | 0.045 | Integral gain — eliminates steady-state error |
| `BALANCE_KD` | 14.0 | Derivative gain — damping |
| `BALANCE_OUT_MAX` | +40 | PID output upper clamp (degrees) |
| `BALANCE_OUT_MIN` | -40 | PID output lower clamp (degrees) |
| `BALANCE_SETPOINT_MM` | 0.0 | Default target position |
| `SEQ_RAMP_RATE` | 30.0 | Setpoint ramp speed (mm/s) |

**Note**: `SERVO_HARD_MIN=10` in balance.h but `SERVO_SAFE_MIN=40` in servo.h — these should be kept in sync. The servo driver clamps to its own limits regardless of balance.h's defines.

## PID Library (`drivers/PID.h`)

```c
typedef struct {
    float Kp, Ki, Kd;
    float integral;
    float last_error;
    float output_max;   // asymmetric: can be positive
    float output_min;   // asymmetric: can be negative
} PID_TypeDef;

void PID_Init(PID_TypeDef *pid, float Kp, float Ki, float Kd, float max, float min);
float PID_Update(PID_TypeDef *pid, float error);  // no dt — rate is implicit
void PID_Reset(PID_TypeDef *pid);                  // zeros integral + last_error
```

Key characteristics:
1. **No dt parameter** — Ki and Kd implicitly include the update rate. Must be called at consistent frequency (K230 frame rate, typically 10-30Hz).
2. **Asymmetric output limits** — `output_max` and `output_min` are independent.
3. **Hardcoded integral clamp** — integral term clamped to ±100.0 internally.

## Servo Driver (`drivers/servo.h`)

Hardware: **TIMA0** PWM on **PA8**, 50Hz (20ms period), 2MHz timer clock.

| Function | Purpose |
|---|---|
| `servo_init()` | Set servo to 90° center |
| `servo_set_angle(uint8_t)` | Set angle, clamped to [SERVO_SAFE_MIN, SERVO_SAFE_MAX] |
| `servo_set_pulse_us(uint16_t)` | Direct pulse width 500-2500us |
| `servo_sweep(target, step_ms)` | Smooth sweep with per-degree delay |

Angle-to-CC formula: `cc = (angle * 4000) / 180 + 1000`

## Debug Output
